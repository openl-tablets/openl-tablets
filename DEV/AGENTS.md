# DEV Module — Core Rules Engine

The foundation of OpenL Tablets. All other modules depend on this. Changes here ripple everywhere.

## Architecture

```
Application Layer (Generated Proxies)  →  Runtime (VM, Context)
  →  Binding (Type Resolution)  →  Parsing (BExGrammar)  →  Source (Excel)
```

**OpenL type system** parallels Java: `IOpenClass` / `IOpenMethod` / `IOpenField` (not Java reflection). Use OpenL types internally; convert at boundaries.

**Binding vs Execution**: compile-time (type checking, method resolution) is strictly separated from runtime. Never mix them.

## Submodules

- **org.openl.rules** — Main engine: type system, parser, binding, bytecode gen, runtime, decision table
  gap/overlap check
- **org.openl.commons** — Shared utilities (`org.openl.util`, `org.openl.message`)
- **org.openl.rules.annotations** — Annotation processing for rules
- **org.openl.rules.gen** — Code generation for bindings
- **org.openl.rules.project** — Project model, instantiation strategies, resource resolution
- **org.openl.rules.test** — Functional test framework (test table implementations). Its
  `test-resources/functionality` holds what a user showcase cannot: regressions of specific defects, expected
  compilation errors and warnings (`.msg.txt`), Java and Groovy interop, engine internals. A behavior users see is
  shown and tested once, in `Example-4-Reference-Guide` of `org.openl.rules.demo`, never again here
- **org.openl.rules.demo** — Demo projects OpenL Studio offers as templates, examples and tutorials. The jar ships
  inside the OpenL Studio war only: it is installed into the local repository but never deployed.
  `DemoProjectsTest` compiles every project and runs its test tables during the build, with dispatching validation
  on as OpenL Studio does, so a demo project ships only without compilation errors and with all its tests passing.
  The `Example-4-Reference-Guide` example has a tested example of every table type, BEX syntax and public,
  non-deprecated built-in function, in workbooks that follow the Reference Guide chapters: a new or changed rules
  feature updates its workbook too
- **org.openl.rules.util** — Rule utility functions
- **org.openl.spring** — Spring integration (`PassCoder` for password encoding lives here) and, in `org.openl.web`,
  the servlet-side helpers OpenL Studio and OpenL Rule Services share, such as the CORS origin list and headers

## Critical Systems — Handle with Extreme Care

### Type System (`org.openl.rules/src/org/openl/types/`)

Core interfaces: `IOpenClass`, `IOpenMethod`, `IOpenField`.

Key implementations:
- `AOpenClass` (abstract base, in `types/impl/`)
- `StaticOpenClass` — wraps a Java `Class`
- `ADynamicClass` — base for types built at runtime (in `types/impl/`)
- `ComponentOpenClass` — composite type (in `binding/impl/component/`)
- `JavaOpenClassCache` — caches Java-to-OpenL type mappings

**Rules**: Never change method signatures on `IOpenClass`/`IOpenMethod`/`IOpenField`. Add new capabilities via new interfaces.

### Parser & Grammar (`org.openl.rules/grammar/bexgrammar.jj`)

JavaCC grammar defining OpenL business expression syntax. Generated sources go to `target/generated-sources/`. After grammar changes:

```bash
cd DEV/org.openl.rules && mvn clean compile && mvn test
```

**Gotchas**: Watch for shift/reduce conflicts in JavaCC output. Always test backward compatibility.

**Identifiers** follow `Character.isJavaIdentifierStart`/`isJavaIdentifierPart` of the running JDK. The `START` and
`PART` classes match ASCII exactly and take any other character but the ellipsis `…`; the lexical action
`checkIdentifier` rejects the non-ASCII ones Java does not accept with `TableNameChecker.indexOfInvalidChar`, the rule
the binders check table, field and parameter names with. A new token made of non-ASCII characters is cut out of
`START` too, or an identifier swallows it.

### Binding System (`org.openl.rules/src/org/openl/binding/`)

Type resolution, method binding, overload resolution. Performance-sensitive.

- `ANodeBinder` — abstract base for all node binders (in `binding/impl/`)
- `TypeBoundNode` — result of binding with type info (in `binding/impl/`)
- Node binders for XLS tables live in `org.openl.rules.lang.xls.binding/`
- `XlsDefinitions` — registry of table type definitions

**Rules**: code that runs on every rule call reads and writes array elements through `org.openl.util.ArrayElements`,
never `java.lang.reflect.Array.get`/`set`. Those are native calls the JIT cannot optimize; on a spreadsheet range or a
varargs call they cost more than the rest of the formula.

### Bytecode Generation (`org.openl.rules/src/org/openl/rules/runtime/`)

Uses ASM (version in root `pom.xml` → `asm.version`). `RulesEngineFactory` is the main entry point for compiling rules. Use `ASMifier` to verify generated bytecode when making changes.

### Project Instantiation (`org.openl.rules.project/src/.../instantiation/`)

- `RulesInstantiationStrategy` — interface for rule loading strategies
- `SimpleProjectEngineFactory` / `SimpleProjectEngineFactory.SimpleProjectEngineFactoryBuilder` — builder pattern for project compilation
- `SimpleMultiModuleInstantiationStrategy` — multi-module loading

### Workbook Loading (`org.openl.rules/src/org/openl/rules/lang/xls/load/`)

A module's Excel workbook is held behind a `WeakReference` (`UnloadableLazyWorkbookLoader`) whenever the dependency
manager allows unloading, and `LazySheetLoader.getSheet()` reads the file again once it has been collected. What a
write changes lives only in that workbook until it is saved, so it must not be collected before then.

**Rules**: every path that changes a workbook asks for it through `XlsSheetGridModel.getSheetToWrite()` or
`getWorkbookToWrite()`, which marks it modified and keeps it in memory until
`XlsWorkbookSourceCodeModule.save()` clears the mark. Reading through `getSheet()` and writing into what it
returned loses the change whenever the workbook is collected in between.

**A moved cell keeps what it stores.** Inserting and deleting rows or columns, merging cells and moving a table
within its workbook (`TableBuilder.writeGridTable`) move a cell with `IWritableGrid.copyCellValue` and its style as it
is; a cell a merge covers stays empty. Reading a value and writing it back stores it differently:
`24` as `24.0`, a date in a new style of the default date format, a text trimmed and without the fonts of its parts.
Every moved cell then shows as changed in a diff and in a merge of the workbook. A number written anew is stored as
Excel stores it, a whole one without a fraction (`PoiExcelHelper.setNumber`, `setDate`).

A saved workbook says so (`XlsWorkbookSourceCodeModule.isSavedSinceRead()`): what was compiled from it no longer
answers for the file. A compilation reads every workbook again, so the mark belongs to one compilation, and OpenL
Studio tells by it whether what it compiled is out of date.

A save never writes over a file another program changed since the workbook was read or last saved: it throws
`WorkbookChangedOutsideException` and leaves the file alone. The workbook remembers the size and the modification
time of its file when it is compiled, and a digest of the snapshot of the file its loader read it from; a workbook
unloaded and read again from other content is not saved either. A save writes
the whole workbook beside the file and replaces the file in one step (`org.openl.util.FileReplacement`), comparing
the file once more right before; never write a workbook file through a stream of your own. A workbook built with an
explicit `WorkbookLoader` is compared by size and time only. A file the file system refuses to replace — held open by
another program, as Excel does on Windows, or read-only — is reported as `org.openl.util.FileLockedException`. A
file no other file can take the place of — in a folder that takes no new file, or mounted into a container on its
own — is written over in place. See [`changes-made-outside.md`](../Docs/architecture/changes-made-outside.md).

**One thread at a time**: a `Workbook` is an Apache POI object over an XmlBeans store, and neither is safe to
touch from two threads. A write racing a save leaves the store's cursor list with a broken link — which spins at
a whole core until the server is restarted — fails the store's own assertion halfway through the save, or writes
a cell at index -1. `ParsedGrid` hands the writable grid to the thread that took the sheet up and answers
everybody else with the sheet as it was parsed; Studio queues the writes of one session behind one another
(`WorkbookWrites`). Anything new that changes a workbook belongs inside that queue.

### Decision Table Gap/Overlap Check (`org.openl.rules/src/org/openl/ie/constrainer/`)

`ValidationAlgorithm` compiles the condition formulas of a decision table with parameters of the types `IntExp`,
`IntBoolExp` and `IntBoolVar`, and `DTChecker` searches the results for gaps and overlaps. Only `Constrainer`,
these expression types, `DTChecker` and its results `Uncovered` and `Overlapping` are public; the rest of the
package is package-private.

**Rules**: OpenL binds the operators of the formulas to the public methods of these types by name — `add`, `eq`, `lt`,
`le`, `gt`, `ge`, `and`, `or` — so no Java code calls most of them. Never rename or remove them. `CastFactory` refuses
any cast from an `IntExp`, so that an operator does not bind to an `Object` overload instead.

## Rule Utility Libraries (`org.openl.rules.util`)

**Registration**: every new class must be added to `org.openl.conf.LibrariesRegistry` via `DEFAULT.addJavalib(YourClass.class)` in its `static` initializer. Forgetting this leaves the methods invisible to rules.

**Reference example**: a new public function gets an example with a test in the matching `7-Functions` workbook of
`DEV/org.openl.rules.demo/src/org.openl.rules.demo.examples/Example-4-Reference-Guide`, which shows every public,
non-deprecated built-in function to users.

**Boxed-type-only public API**: never expose primitive overloads (`int`, `long`, `float`, `double`, `byte`, `short`). OpenL compiles rule variables to boxed types internally, so primitive variants add no performance benefit and bloat the method-dispatch search space. Keep primitive arithmetic in **private** helpers; public methods accept and return `Byte` / `Short` / `Integer` / `Long` / `Float` / `Double` / `BigInteger` / `BigDecimal`.

**Decimal arithmetic of doubles**: the operators `add`, `subtract`, `multiply`, `divide`, `rem`, `inc`, `dec` of
`double`/`Double` and the functions `remainder`, `quotient`, `floorDiv`, `mod` of `Double` compute with the decimals
the numbers show through `org.openl.rules.util.DecimalArithmetic`, so `0.1 + 0.2` is `0.3`. A number of 16 or 17
digits with a fraction is a computed one and counts as its double, and a result of it within the rounding it carries
of a decimal of at most 13 digits is that decimal (`DecimalArithmetic.snap`), so `1 / 3 * 3` is `1`. A function
documented to give the same result as an operator computes through it too, never with the Java operators.

**Exact products of doubles**: the decimal arithmetic takes the rounding error of a product and the rest of a quotient
from `ExactProduct`, never from `Math.fma`. Without the fused multiply-add instruction — x86-64 before Haswell, or a
virtual machine that hides it — the JVM computes `Math.fma` with `BigDecimal`, hundreds of times slower, while
`ExactProduct` splits the factors and runs equally fast on every processor.

**Array result types**: a function that returns an array keeps the type of the array it gets, so `int[]` gives
`int[]`. Only `add`, `addAll`, `addElement` and `flatten` change it, to the closest common type of the elements: an
added `Integer` gives `Integer[]`, a `double` gives `double[]`, and a boxed type keeps the result boxed. Write
such a function generically and mark it `@ArrayResultType` (`org.openl.rules.annotations`): the engine reports the
array type and converts the boxed result back, so no primitive overload is needed.

cd STUDIO && mvn clean install -DskipTests

## Known Technical Debt

- `JavaOpenClassCache` (`types/java/`) — potential memory leak (needs review)
- `RuleRowHelper` (`rules/binding/`) — string interning may cause memory issues
- `ComponentOpenClass` (`binding/impl/component/`) — calls methods in constructor
- `TypeBoundNode` (`binding/impl/`) — static method access design issue
- `TypeResolver` (`conf/`) — missing security blocking for system class access
- `CastToWiderType` (`binding/impl/`) — missing generic type support
- `NewArrayNodeBinder` (`binding/impl/`) — incomplete array dimension initialization
